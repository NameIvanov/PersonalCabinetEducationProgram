# Проверка PDF ОПОП: MVP руководителя

## Использование

В кабинете руководителя нажмите **Проверить PDF** у конкретного файла. Для комплекта сначала выберите файл в разделе управления файлами. При необходимости выберите предыдущий PDF из истории **того же элемента**. Это явный выбор: одинаковое имя не доказывает, что два файла — версии одного документа.

Кнопка **ИИ-помощник** в шапке доступна руководителю, согласующему и модератору. Она открывает выбор только доступной ОПОП и PDF. У согласующего/модератора кнопка также есть рядом с файлом; страница сообщает, что их этапы анализа ещё не включены, и позволяет открыть выбранный PDF. Администратор сохраняет собственную кнопку существующего административного помощника. Логотип ведёт через `Account/RedirectByRole`, а для анонимного посетителя — на вход.

Проверка работает в фоне, страницу можно закрыть. Результат содержит технические статусы страниц, замечания, точные цитаты, уверенность, объяснение и рекомендации. **Учесть** и **Не является ошибкой** сохраняют решение и необязательный комментарий. Исправления вносит человек; после загрузки нового PDF можно сравнить его с предыдущим и открыть историю предыдущих проверок. В истории файлов также есть ссылка **Проверки PDF**.

Помощник не вызывает `ElementWorkflowService`, не отправляет документ на согласование, не меняет статусы, не публикует и не отклоняет документы. Пустой список замечаний не означает одобрение документа.

## Конфигурация

Секция `DocumentAnalysis` независима от `Ai` административного помощника. По умолчанию облачный анализ отключён, OCR не настроен, обязательный шаблон отсутствует. В этих случаях результат явно сообщает о неполной проверке.

Пример для **согласованного организацией** шаблона (перечни ниже демонстрационные, не универсальные нормативные требования):

```json
{
  "DocumentAnalysis": {
    "MaxFileBytes": 20971520,
    "MaxPages": 200,
    "MaxTextCharacters": 120000,
    "AnalysisTimeoutSeconds": 120,
    "QueueCapacity": 20,
    "MaxQueuedPerUser": 2,
    "MaxQueueWaitSeconds": 900,
    "MaxFindings": 40,
    "DotnetExecutable": "dotnet",
    "OcrExecutable": null,
    "OcrLanguages": "rus+eng",
    "OrganizationKey": "university",
    "SemanticAnalysisEnabled": false,
    "Endpoint": "https://api.groq.com/openai/v1/chat/completions",
    "Model": "",
    "ProviderTimeoutSeconds": 45,
    "Templates": [
      {
        "Id": "discipline-bachelor",
        "Version": 1,
        "OrganizationKey": "university",
        "ElementType": "Discipline",
        "EducationalLevel": "Бакалавриат",
        "RequiredSections": ["Цели освоения дисциплины", "Планируемые результаты обучения"],
        "RequiredFields": ["Общая трудоёмкость"]
      }
    ]
  }
}
```

Добавьте секцию в конфигурацию развёртывания. `ApiKey` передавайте через `DocumentAnalysis__ApiKey` или user-secrets. Для смысловой проверки задайте поддерживаемую провайдером модель, ключ, HTTPS endpoint с OpenAI-compatible `chat/completions` и `SemanticAnalysisEnabled=true`. Провайдер должен поддерживать `response_format: json_object` и `max_tokens`. Автоматического переключения на другой облачный сервис нет. Тесты используют подставной HTTP-провайдер, реальный облачный вызов при разработке не выполнялся.

Для организации используется `OrganizationKey` всего экземпляра приложения: в существующей модели нет отдельного арендатора/организации. Шаблон выбирается по организации, типу элемента и уровню образования. `*` разрешён для типа и уровня; точный тип имеет приоритет, затем точный уровень. При равной специфичности используется первый шаблон в конфигурации. Редактирование конфигурации — задача оператора, отдельной формы управления шаблонами в MVP нет. Каждая проверка сохраняет снимок выбранного шаблона и его версию.

## PDF и OCR

Извлечение выполняет [PdfPig](https://github.com/UglyToad/PdfPig) 0.1.11 в отдельном .NET-процессе. Используется `ContentOrderTextExtractor`, номера физических страниц начинаются с 1. Это не номера, напечатанные в колонтитулах. Подпроцесс запускается до инициализации web host, не читает конфигурацию приложения и получает ограниченный набор переменных окружения. stdout используется только как ограниченный протокол передачи данных в памяти, не как журнал.

Для локального OCR установите **OCRmyPDF**, его системные зависимости и языковые данные Tesseract `rus`/`eng`, задайте путь к исполняемому `OcrExecutable`. Он вызывается напрямую без shell с `--skip-text --rotate-pages --deskew --jobs 1 --tesseract-timeout 30`. Эти режимы описаны в [документации OCRmyPDF](https://ocrmypdf.readthedocs.io/en/stable/cookbook.html). Развёртывайте его в совместимой среде; строка с командами WSL/Docker вместо пути к исполняемому файлу не поддерживается. При необходимости используйте проверенный локальный executable-адаптер или замените `IPdfTextExtractor`.

Распознанный PDF временный; исходный файл не меняется. После обработки временный результат удаляется. Текст целиком не сохраняется в БД, административных диалогах или журналах. Сохраняются только ограниченные цитаты, замечания, реакции, технические признаки страниц и фрагменты различий.

Ограничения распознавания:

- Пустой считается страница без извлекаемого текста, изображений и векторных путей. Полностью белое изображение скана нельзя достоверно отличить от нераспознанной страницы: выводится OCR/ручная проверка, а не утверждение о пустоте.
- Поворот берётся из PDF; ориентацию изображения без `/Rotate` исправляет настроенный OCR. Без OCR она не определяется.
- Низкая читаемость текстового слоя определяется по повреждённым символам и доле букв/цифр. У скана дополнительно выявляются крупные изображения с разрешением ниже 100 DPI. Это эвристики, не полное измерение визуального качества или точности OCR.
- Страницы с существующим текстом не перераспознаются (`--skip-text`). Повреждённый существующий слой остаётся на ручную проверку.
- Цитаты OCR — точные фрагменты распознанного слоя, а не гарантия совпадения с изображением; они помечены, уверенность ограничена 70%, итог требует ручной проверки.
- OCR, парольные/повреждённые документы и превышение лимитов никогда не приводят к придуманным замечаниям. OCR на этом рабочем месте не установлен; реальный OCR-интеграционный прогон остаётся проверкой развёртывания.

## Проверки и сравнение

Код проверяет календарные даты, шифр и явно подписанное название программы относительно карточки, явные суммы вида `a + b = total`, повторяющиеся подписанные реквизиты даты реализации и часов, обязательные разделы/поля по выбранному шаблону. Поиск разделов нормализует регистр и пробелы. При отсутствии текста хотя бы на одной непустой странице отсутствие раздела не утверждается.

Для отсутствующего раздела цитата является обозначенным фрагментом начала документа, а не «цитатой отсутствующего текста». Такой результат просит проверить альтернативное название. Контекстные противоречия и неочевидные ошибки анализирует ИИ. Внешний ответ проходит ограничения длины/количества и проверку наличия точной цитаты на указанной странице. Неверные замечания отбрасываются с сообщением о неполноте анализа. Уверенность ИИ — оценка модели, а не измеренная вероятность ошибки.

Сравнение предыдущего PDF выполняется **локально**. LCS сопоставляет неизменённые страницы, выделяет добавление, удаление и замену текста. Различия помечают даты, шифры, числовые значения/часы, строки таблиц и заголовки/реквизиты. Хранятся ограниченные фрагменты вокруг первого изменения страницы и сводка количества изменений. Это текстовое сравнение, не распознавание структуры ячеек, визуального оформления, подписей или изображений. Изменения в таких объектах и сложные переносы между страницами требуют визуальной сверки. Нечитаемая версия делает сравнение явно неполным.

## Данные, доступ и очередь

`DocumentAnalysis` привязан к `EducationalProgramElementFile.Id`, `RevisionNumber` и SHA-256. Замена файла в текущей итерации создаёт новый ID даже при прежнем `RevisionNumber`. В повторном запуске создаётся новая проверка актуального содержимого и снимка шаблона; старые решения остаются в истории. Только одновременные активные запросы одного файла объединяются. Полный текст не используется как persistent cache.

Новые таблицы:

| Таблица | Назначение |
| --- | --- |
| `document_analyses` | Автор/время, версия/хэш, выбранный предыдущий PDF/хэш, шаблон, статус и поля очереди |
| `document_findings` | Замечание, страница, цитата, уверенность, происхождение OCR, статус |
| `document_finding_feedback` | Неизменяемая история реакций, автор, время и комментарий |
| `document_page_diagnostics` | Признаки страниц без полного текста |
| `document_page_changes` | Страницы и ограниченные фрагменты различий |

Все маршруты MVP доступны только Manager/Admin и вызывают `DocumentAnalysisAccessService`, использующий существующий `ElementAccessService`. ID анализа/замечания проверяется через связанный файл. Предыдущий PDF дополнительно ограничен тем же элементом и более ранней загрузкой. Архивы исключаются существующим сервисом. Обновления защищены antiforgery и rate limiting; результаты отдаются с `no-store`. Оптимистическая конкуренция предотвращает потерю одновременно изменяемой реакции.

Фоновый обработчик восстанавливает текущую роль из Identity, проверяет подтверждение/блокировку пользователя, назначения, архивирование и состояние файла до чтения, перед облачным вызовом и перед сохранением. SHA-256 проверяется при постановке, до/после извлечения и до/после смыслового анализа. Облачный адаптер получает исключительно страницы выбранного PDF; ему не передаются предыдущая версия, карточки других ОПОП, журналы, диалоги, реакции пользователей или секреты в контексте.

Очередь хранится в БД. Уникальные nullable `QueueSlot`, `ActiveKey`, `UserQueueKey` ограничивают общее количество задач, повторы одного файла и задачи пользователя при конкурентных запросах. Один обработчик на экземпляр; конкурентное получение задачи защищено токеном версии. Ожидающие задачи переживают перезапуск. Зависшие/прерванные задачи переходят в явный Failed после дедлайна и освобождают слот; автоматических повторных облачных запросов нет. Весь разбор/сравнение/OCR/ИИ ограничен общим таймаутом; дочернее дерево процессов завершается при отмене. Физические лимиты памяти/CPU для продакшена задаёт среда развёртывания.

Миграция: `20260907203923_AddDocumentAnalysis` (+ designer и актуальный snapshot). Существующая пользовательская миграция `20260907201000_AddPersistentAiAssistantState` сохранена. Миграция проверяется генерацией SQL и соответствием модели; живой MySQL при разработке не мигрировался. Приложение по существующему правилу вызывает `MigrateAsync` при запуске. Длинный снимок шаблона хранится в `longtext`, чтобы не превысить ограничение размера строки MySQL.

## Расширение на этапы 2 и 3

`DocumentAnalysisPurpose` уже содержит `ManagerPreflight`, `ApproverReview`, `ModeratorPublication`. Доступ сопоставлен с действующими `CanManageElementAsync`, `CanApproveElementAsync`, `CanModerateElementAsync`. Общий `DocumentAssistantController` открывает выбор PDF всем ролям; **запуск анализа** этапов 2/3 пока не открыт. При внутренней фильтрации списка проверка доступа не записывает ложные IDOR-события; явный запрос чужого файла использует обычную регистрацию отказа. Тесты проверяют будущие политики, включая назначения согласующего и чужую ОПОП.

Для следующих этапов добавляйте стратегии по `Purpose`: подбор утверждённой/опубликованной базы сравнения, смысловые требования согласующего и проверки публикации/персональных данных. Извлечение, доказательства, история реакций, сравнение и очередь переиспользуются. Для запуска новых целей нужно расширить допуск контроллера/входной сервис и правила допустимого состояния PDF: текущий enqueue намеренно принимает только preflight руководителя. Любой новый облачный prompt должен сохранять тот же предел контекста — один выбранный PDF. Сравнение двух документов остаётся локальным.
